# Behavior Suite Mutation Control

## Status: Completed

## Context

`tests/test_royalmail.py` is the only defense for several shipped guards, yet
nothing observed it rejecting a defect. Verification asserted that test source
text exists — `scripts/check-docs-plans.py` pins individual test names and
assertion literals — while never planting a defect and requiring the suite to
fail.

Two consequences were measured on `62d075e`:

- The header-injection guard (`royalmail.py` `_safe_header_value`) is pinned by
  no checker. Neutering it to `if False:` is caught only by the suite.
- `tests/` is not closed-world. Adding `tests/test_aaa_shadow.py`, which needs
  no edit to any pinned file, rebinds `unittest.TestCase.run` to report success
  without executing a test. With that file present and the guard neutered,
  `make check-python3` printed `Ran 38 tests ... OK` and exited 0.

A text pin cannot notice a neutered assertion mechanism, because the assertion
mechanism is not text in a pinned file.

## Scope Boundaries

- Do not change RoyalMail behavior, SMTP ownership, message headers,
  attachments, dependencies, or the mandatory Python 2 compatibility boundary.
- Preserve pinned hosted Python 2.7.18 and Python 3.12.8 verification.
- Do not add dependencies, generated bytecode, or network calls.
- No live SMTP relay or credentials.

## Work Completed

- Added `scripts/test_behavior_mutations.py`. It copies the checkout to a
  throwaway tree, plants each hostile mutation, runs the real suite, and fails
  if any mutation survives. A disabled suite always passes, so every mutation
  survives and the harness fails: the shadow module and the neutered assertion
  mechanism are caught by construction rather than by pinning.
- Added a clean-tree control so universal failure cannot masquerade as
  detection.
- Ran the harness under both runtimes from `contract-test-python2` and
  `contract-test-python3`, the targets the hosted workflow already reaches
  through `make check-python2` and `make check-python3`.
- Derived the `check-docs-plans.py` guard from the harness's real `MUTATIONS`
  table instead of pinning prose about it, so reducing the harness to a success
  message fails verification and every planted defect must name a line
  `royalmail.py` actually ships.
- Added `test_rejects_trailing_newline_in_attachment_mimetype`. The harness
  surfaced this coverage gap: `MIME_TOKEN_RE` anchors with `$`, which matches
  before a trailing newline, so `text/plain\n` clears the token check and the
  explicit newline guard is its only defense. `CONTENT_ID_RE` already anchors
  with `\Z` and needs no equivalent test, so no mutation is claimed for it.

## Verification Completed

- `make check-python3` passed: 39 behavior tests, 19 workflow, 13 manager, and
  14 SMTP contract mutations rejected, and 5 hostile behavior mutations
  rejected.
- `make check` and `make verify` additionally run the 165 Make authority cases;
  `check-python2` was not executed locally because Python 2.7 is unavailable
  outside the pinned container, and the hosted job covers it.
- Attacked the new control: the shadow module that previously produced
  `Ran 38 tests ... OK` at exit 0 now makes all 5 mutations survive, and the
  harness fails with `hostile mutation survived the behavior suite`.
- Reducing the harness to its success message fails `check-docs-plans.py`.
- No live SMTP relay or credentials were used.
