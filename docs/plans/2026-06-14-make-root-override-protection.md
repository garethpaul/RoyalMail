# Make Root Override Protection

## Status: Completed

## Context

RoyalMail derives a repository root from its Makefile and uses that path for
both mandatory Python runtime gates. Because GNU Make command-line variables
outrank an ordinary assignment, `make ROOT=/tmp check` can redirect those
commands away from the checkout and weaken the location-independent contract.

## Requirements

- **R1:** Prevent command-line and environment values from replacing the
  Makefile-derived repository root.
- **R2:** Keep `PYTHON2` and `PYTHON3` configurable.
- **R3:** Require the exact protected declaration in the Python 2/3-compatible
  documentation checker.
- **R4:** Prove the canonical runtime gates from the checkout and an external
  directory with a hostile `ROOT` argument.
- **R5:** Preserve mail composition, SMTP behavior, manager queue accounting,
  workflow policy, and bytecode-free verification.

## Implementation Units

### U1. Protected Root

Give the repository-derived `ROOT` declaration override precedence without
changing any recipe or runtime-selection behavior.

### U2. Dual-Runtime Static Contract

Extend `scripts/check-docs-plans.py` to reject weakened, duplicate, displaced,
or caller-controlled root declarations on both supported runtimes.

### U3. Verification

Run focused contracts, canonical Python 2 and Python 3 gates, hostile external
execution, digest-pinned containers, mutations, and integrity screening.

## Scope Boundary

- Do not change `royalmail.py`, public APIs, callback ordering, or queue logic.
- Do not change workflow actions, runtime versions, or required coverage.
- Do not add dependencies, generated bytecode, or credentials.
